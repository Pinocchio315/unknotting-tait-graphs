# lower_bounds/greene — correction terms of the double branched cover from a knot diagram

This guide covers the Greene calculations in manuscript **v1.8**. The frozen
`v1.3` sweep below is preserved. Its
[four extensions](../../results/extensions_2026-09-10/lower/README.md) raise
the sweep totals to 1,711 lower-bound improvements: 1,496 additional exact
values and 215 ranges. With the two original BJ computations the lower-stage
exact count is 1,498. Ten remaining ranges are settled by new upper bounds.

The obstructions of Section 3 compare the correction terms of `Σ₂(K)` with the definite forms allowed by
an unknotting sequence.  For an alternating knot the correction terms come from the sharp Goeritz form.
This directory removes that restriction: when the reduced Khovanov homology over `F₂` has rank equal to
the determinant, the branched-cover spectral sequence makes `Σ₂(K)` an `L`-space, and Greene's
spanning-tree model gives finite candidate sets for the correction terms. Intersecting the sets from
different markings may determine every value. If some values remain ambiguous, all surviving candidate
vectors are tested; only their unanimous exclusion gives an obstruction. The same comparison with
definite forms therefore applies to these non-alternating knots.

The method was written to decide `u(12n491)`, the knot left open by Brittenham and Hermiller's
counterexample to the Bernhard–Jablan conjecture ([arXiv:1705.05985](https://arxiv.org/abs/1705.05985)).
The original frozen sweep supplies 1,707 improved lower bounds, including 1,492 additional exact values.
Together with `12n491` and `13n3370`, it accounts for 1,494 exact values in the paper's historical
comparison. An exact value always combines the obstruction with a separately established upper bound.

## Orientation and candidate correction terms

The absolute gradings and `Spin^c` labels come from Greene's Theorem 4.1 and §4.5, for the oriented
branched cover `Σ₂(K)`. His Lemma 6.7 shows that the higher-rank summands of `(E₀, d₀)` are acyclic;
the rank-one summands are generated by solitary states. These finite free complexes retain that
description over `F₂`, so Theorem 6.8 also gives the solitary-state `E₁` page with these coefficients.
Its grading and `Spin^c` decomposition ensure that the correction term of an `L`-space belongs to the
solitary-state grading set in that class. See [Greene's paper](https://arxiv.org/abs/0805.1381).

For the rank-two through rank-four tests, the **signature fixes the orientation**. The function
`oriented` negates a candidate vector when `sigma < 0`, using `d(-Y,t) = -d(Y,t)`. The mirrored knot
then has `sigma = 2n`; an unknotting sequence of length `n` would have only negative crossing changes,
so the positive-definite filling in [Owens's Theorems 3 and 5](https://arxiv.org/abs/math/0506485)
applies. The sign of a spin entry is not used to choose between the two orientations.

For an `L`-space double branched cover of a knot, `d(spin) = -sigma/4` follows from
[Lin–Ruberman–Saveliev, Theorem A and Remark 1.1](https://arxiv.org/abs/1802.07704): the reduced Floer
group vanishes, so their Lefschetz formula gives `h = sigma/8`, and `d = -2h`. The `F₂` `L`-space
condition used here implies the rational `L`-space condition by the universal coefficient theorem;
the unique class in each `Spin^c` summand has the same absolute grading over both fields.

After orienting the vector, `rank_test` checks the spin entry `d(0) = -n/2`. The implementation retains
the conservative behavior used in the deposited run: a candidate with a different spin entry returns
`ERROR`, and the presence of such a candidate makes the knot `UNDECIDED`. It is not silently discarded
before testing the other candidates. A bound is recorded only when the spin entry is fixed as required
and every remaining complete candidate vector is excluded. The other correction terms need not be
uniquely determined. The linking-form pre-filter separately allows both pairing-sign
conventions, which weakens that filter without changing the orientation of the correction-term vector.

For `u = 1`, the Ni–Wu routine instead tests both orientations and every affine identification of
`Z/D`, without a linking-form filter. A `PASS` in either routine means that a necessary surgery
comparison has a surviving candidate. It does **not** construct an unknotting sequence or prove the
tested value of `u`.

## The sweep

`build_greene_targets.py` selects the knots to which a test applies.  A knot qualifies when it is
non-alternating, its reduced mod-2 Khovanov homology has rank equal to the determinant, and
`H₁(Σ₂(K))` is cyclic. The worker rechecks the frozen mod-2 vector and the
signature/test hypotheses before computing a bound. A range `[1, b]` with
`|σ| <= 2` selects the Ni–Wu test for `u = 1`; a range `[n, b]` with
`|σ| = 2n` selects the rank-`n` test. A completed obstruction excludes
`n` crossing changes and raises the lower bound to `n + 1`.

    targets   1967   u1 1521, rank2 385, rank3 54, rank4 7
    controls  1452   u1 574, rank2 640, rank3 210, rank4 28

A control has a known unknotting number equal to `n`, so the obstruction must not fire on it; the sweep
reports an obstructed control as an implementation error and exits nonzero.

The deposited inputs are
[`greene_targets_2026-09-08.json`](../../results/greene/greene_targets_2026-09-08.json), with diagrams
and mod-2 Khovanov vectors from `database_knotinfo==2026.8.1`. Their ranges precede the sweep and include
the earlier results for `12n491` and `13n3370`. To replay one target, run from the repository root:

```sh
python lower_bounds/greene/greene_sweep.py \
  --targets results/greene/greene_targets_2026-09-08.json --one 13n_111
```

To reproduce **selection** as well, reconstruct the table before the sweep in a separate directory,
then explicitly pass it to the builder (also from the repository root):

```sh
python consolidate_results.py --profile pre-sweep --outdir /tmp/unknotting-before-greene
python lower_bounds/greene/build_greene_targets.py \
  --table /tmp/unknotting-before-greene/u_table.json \
  --out /tmp/unknotting-before-greene/greene_targets.json
```

The builder must use `database_knotinfo==2026.8.1` for this comparison. Compare cohort membership and
record contents with the deposited input; the `source.ranges` path naturally differs. Its default
`generated/u_table.json` may contain the sweep's conclusions and must not be used to reconstruct the
historical selection. The deposited input remains the source for replaying the recorded experiment.

The builder records the first unsuccessful filter for each excluded entry. Starting with the 12,965
knots in the comparison table, it excludes 6,729 alternating knots, then 1,682 entries whose mod-2
Khovanov rank equality is not established, 290 whose cyclic first homology is not established, and
845 whose signature does not satisfy the selected test. The remaining 3,419 entries form the targets
and controls above. The middle two categories include unavailable or unusable input fields; they
should not be interpreted as proofs of non-thinness or non-cyclicity for every excluded knot.

### Optional cluster runs

The remaining launch commands are run from `lower_bounds/greene/`.
`make_server_package.py` collects the modules of this
directory, the form enumerations of `../owens`, and the **local**
`data/greene_targets.json` into one flat directory, so
the server needs only `numpy`, `sympy` and the standard library.  The KnotInfo database, SnapPy and the
rest of the repository are not required. For a replay of the paper's sweep,
first check that this local input is identical to the archived
`../../results/greene/greene_targets_2026-09-08.json`; it may have been
replaced by a later call to the target builder. The packager does not accept
`--targets`. Its `--out` directory is replaced if it already exists, so use
a fresh destination for a new campaign.

```sh
python make_server_package.py --out /tmp/greene-v16-replay
scp /tmp/greene-v16-replay.tar.gz SERVER:~/
ssh SERVER "tar xzf greene-v16-replay.tar.gz && cd greene-v16-replay && sbatch slurm_greene.sh"
```

Sixteen array tasks each take one sixteenth of the work.  A task sweeps its share of the controls first
and goes on to the targets only if none of them is obstructed, so an implementation error stops the job
before any target is computed.  Resubmitting the same command resumes: a completed verdict already recorded in the
output file is skipped; errors and timeouts are retried. An obstructed control recorded by an earlier
run also stops resumption, so it cannot be bypassed by rerunning the launcher.

The rank-four enumeration is much slower than the rest.  To keep it out of the main job and run it
separately:

```sh
sbatch --export=ALL,SKIP=rank4 slurm_greene.sh
sbatch --export=ALL,TEST=rank4,ARRAY_SIZE=4 --array=0-3 slurm_greene.sh
```

`bash slurm_greene.sh --dry-run` prints the resolved commands without running them.  Each task writes
`runs/<set>/results_<set>_<task>_<size>.jsonl`, one line per knot. Runtime depends on the diagram, the
number of candidate vectors and the definite forms that survive the linking comparison. The
rank-four enumeration is particularly slow and has its own submission line above.

Verdicts: `OBSTRUCTED` raises the lower bound, and `PASS`, `UNDECIDED`, `TIMEOUT` and `ERROR` supply no
bound.  A time limit is not a negative mathematical result.

The archived sweep is
[`sweep_2026-09-08.jsonl.gz`](../../results/greene/sweep_2026-09-08.jsonl.gz). All 22 control `TIMEOUT`
records report 300.0 elapsed seconds. This historical observation should be distinguished from the
current CLI and Slurm defaults of **10,800 seconds per knot**, configurable with `--time-per-knot`
and `TPK`, respectively. `--one` runs the calculation directly; the timeout is applied by the parent
worker process in a sweep. The two terminated targets `13n4876` and `13n4973` have return code `-15`,
and `13n5102` has no completed record. None supplies a bound.

There is **no cap on the number of candidate vectors**: the Cartesian product over conjugate pairs
is exhausted for each completed record. The maximum recorded number is `6,561 = 3⁸` for `13n1619`;
the maximum among obstructed knots is 243 for `13n4236`. For `13n1619`, 15 classes remain ambiguous,
giving eight independent choices after conjugation, and six vectors admit the Ni–Wu comparison.
This is the sole survivor among the 1,521 targets tested for `u = 1`; its range remains `[1,2]`.
These are candidate vectors, and a surviving one has not thereby been shown to be the actual vector.

The spin-entry guard occurs in the records for controls `11n107`, `12n296`, `12n590`, `12n609`,
`12n661`, `13n1902`, `13n2355`, `13n2545`, `13n3685`, and target `13n2731`. Each has an ambiguous
spin entry and also has a candidate that passes the comparison. All ten remain `UNDECIDED`; these
records do not give counterexamples to the spin correction-term identity. The other 1,421 completed
controls pass a comparison, and no control is obstructed.

The 1,707 exclusions consist of 1,520 for `u = 1`, 140 in rank two, 43 in rank three, and four in

`UNDECIDED` record is included in completion counts but is not counted as a passing comparison.

A run split between the cluster and another machine leaves several result files.  `summarize_greene.py`
reads any number of them, rejects malformed records, keeps one record per knot (a conclusive verdict replaces an error or a
timeout, while different completed verdicts for one knot stop publication of the summary), states the
coverage against the frozen list, checks controls by membership in that list, and writes the bounds only
if no inconsistent verdict or obstructed control has been found:

From `lower_bounds/greene/`, summarize a new run against its explicitly
selected cohort and write a new output file:

```sh
python summarize_greene.py runs/*/*.jsonl \
  --targets ../../results/greene/greene_targets_2026-09-08.json \
  --out /tmp/greene-new-summary.json
```

To reconstruct the summary of the archived sweep, run from the repository
root. The summarizer reads plain JSONL, so decompress the stored archive
into a separate file first:

```sh
python -c "import gzip, pathlib; pathlib.Path('/tmp/greene-paper.jsonl').write_bytes(gzip.decompress(pathlib.Path('results/greene/sweep_2026-09-08.jsonl.gz').read_bytes()))"
python lower_bounds/greene/summarize_greene.py /tmp/greene-paper.jsonl \
  --targets results/greene/greene_targets_2026-09-08.json \
  --out /tmp/greene-paper-summary.json
```

The input membership and resulting 1,707 improvements should agree with
the deposit. Run-specific path fields may differ. This reconstructs the
summary from the recorded verdicts without rerunning Greene's model.

## Validation

`python greene_ranks.py --validate 5_1 7_3 7_5 8_2 9_10 9_13 7_1 9_3 9_6 9_9 10_2 10_46` recomputes the
correction terms of twelve alternating knots with Greene's model, checks that they agree with the sharp
Goeritz form up to relabelling, and compares the verdict with the published rank-two and rank-three
tests of `../owens/`.  All twelve agree.  On the Montesinos knots `8_20`, `9_43` and `9_44` the pinned
correction terms agree with the star plumbings of `../montesinos/`, and the surgery test admits the
knots of unknotting number one (`3_1`, `4_1`, `5_2`, `8_20`, `9_44`) and excludes `5_1`, `7_4`, `9_43`.
The correction terms of `12n491` were recomputed from an independent minimal diagram and agree.

A missing linking pairing disables the prime-pairing part of the pre-filter; the validation command
supplies the computed pairing and therefore exercises the same filter as the sweep.

The versions listed under [Environment in the main README](../../README.md#environment-for-mathematical-computations) describe the
September 2026 **local audit**, not every historical cluster run. The frozen input records the KnotInfo
package version, but the sweep archive does not contain a complete historical package-and-launch
manifest. Replaying a completed computation with the documented audit environment checks the result;
it does not reconstruct unrecorded historical runtime settings.
